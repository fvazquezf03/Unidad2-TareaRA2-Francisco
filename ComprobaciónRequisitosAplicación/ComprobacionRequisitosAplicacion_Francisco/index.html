    3. Comprobación Requisitos Aplicación

    Código malicioso (V10 – Malicious Code)¶

    En este apartado se han revisado los requisitos del capítulo V10 de OWASP ASVS sobre código malicioso, aplicados al código de la aplicación (main_app.py y lavadero.py). Las verificaciones cubren tanto controles de integridad del código como la ausencia de funcionalidades ocultas o no deseadas.

    Resumen de comprobaciones realizadas¶

    Area # ASVS Level CWE Verification Requirement Valid Source Code Reference Comment Tool Used
    Code Integrity Controls 10.1.1 3 749 Verify that a code analysis tool is in use that can detect potentially malicious code, such as time functions, unsafe file operations and network connections. Non-valid main_app.py, lavadero.py Solo se ha realizado revisión manual; no se ha utilizado ninguna herramienta de análisis estático (SAST) tipo Semgrep o Bandit para detectar código potencialmente malicioso. Malicious Code Search
    Malicious Code Search 10.2.1 2 359 Verify that the application source code and third party libraries do not contain unauthorized phone home or data collection capabilities. Where such functionality exists, obtain the user's permission before collecting any data. Not Applicable main_app.py, lavadero.py La aplicación no realiza conexiones de red ni usa librerías externas con “phone home” o telemetría; solo lógica local en memoria.
    Malicious Code Search 10.2.2 2 272 Verify that the application does not ask for unnecessary or excessive permissions to privacy related features or sensors, such as contacts, cameras, microphones, or location. Not Applicable main_app.py No se ejecuta en móvil ni accede a sensores o permisos de privacidad (contactos, cámara, micro, localización); es una app de consola.
    Malicious Code Search 10.2.3 3 507 Verify that the application source code and third party libraries do not contain back doors, such as hard-coded or additional undocumented accounts or keys, code obfuscation, undocumented binary blobs, rootkits, or anti-debugging, insecure debugging features, or otherwise out of date, insecure, or hidden functionality that could be used maliciously if discovered. Valid main_app.py, lavadero.py Revisión de lavadero.py y main_app.py: no hay cuentas ocultas, claves embebidas, código ofuscado ni funcionalidades escondidas; solo constantes de fase y lógica del lavado.
    Malicious Code Search 10.2.4 3 511 Verify that the application source code and third party libraries do not contain time bombs by searching for date and time related functions. Valid lavadero.py No se usan funciones de fecha/hora; solo un contador de pasos para evitar bucles infinitos, que no actúa como “time bomb”.
    Malicious Code Search 10.2.5 3 511 Verify that the application source code and third party libraries do not contain malicious code, such as salami attacks, logic bypasses, or logic bombs. Valid lavadero.py El método cobrar suma importes fijos y la lógica de fases solo gestiona el flujo del lavado; no hay salami attacks, bypasses ocultos ni logic bombs.
    Malicious Code Search 10.2.6 3 507 Verify that the application source code and third party libraries do not contain Easter eggs or any other potentially unwanted functionality. Valid main_app.py, lavadero.py Todas las funciones forman parte del comportamiento normal (simulación, impresión de estados); no se han encontrado Easter eggs ni funcionalidades no documentadas.
    Deployed Application Integrity Controls 10.3.1 1 16 Verify that if the application has a client or server auto-update feature, updates should be obtained over secure channels and digitally signed. The update code must validate the digital signature of the update before installing or executing the update. Not Applicable main_app.py La aplicación no tiene mecanismo de auto-actualización ni descarga código ejecutable; se distribuye como script Python estático.
    Deployed Application Integrity Controls 10.3.2 1 353 Verify that the application employs integrity protections, such as code signing or subresource integrity. The application must not load or execute code from untrusted sources, such as loading includes, modules, plugins, code, or libraries from untrusted sources or the Internet. Not Applicable main_app.py, lavadero.py No se cargan módulos, plugins ni código desde fuentes externas o Internet en tiempo de ejecución; solo se importa Lavadero desde un módulo local.
    Deployed Application Integrity Controls 10.3.3 1 350 Verify that the application has protection from subdomain takeovers if the application relies upon DNS entries or DNS subdomains, such as expired domain names, out of date DNS pointers or CNAMEs, expired projects at public source code repos, or transient cloud APIs, serverless functions, or storage buckets or similar. Not Applicable main_app.py La aplicación no depende de DNS, subdominios ni recursos en la nube; se ejecuta localmente sin dominios configurados.

    Conclusiones sobre código malicioso¶

    • No se han encontrado puertas traseras, time bombs, salami attacks, Easter eggs ni funcionalidades ocultas; el comportamiento del código coincide con la lógica de negocio descrita.
    • El único control marcado como Non-valid es el uso de herramienta SAST (10.1.1); sería recomendable integrar en el flujo de desarrollo una herramienta como Semgrep o Bandit para mejorar la detección de código potencialmente malicioso.

    Validación de entrada (V5 – Input Validation)¶

    En este apartado se han revisado los requisitos del capítulo V5 de OWASP ASVS aplicables al nivel de seguridad definido para la aplicación del lavadero (main_app.py y lavadero.py). Dado que se trata de una aplicación de consola sin entrada libre de usuario, muchos controles orientados a entornos web o APIs han resultado Not Applicable.

    Resumen de comprobaciones realizadas¶

    Area # ASVS Level CWE Verification Requirement Valid Source Code Reference Comment Tool Used
    Input Validation Requirements 5.1.1 1 235 Defensas frente a HTTP parameter pollution. Not Applicable main_app.py, lavadero.py No hay endpoints HTTP ni parámetros GET/POST/cookies/headers; la app solo usa booleanos internos controlados por el propio programa.
    Input Validation Requirements 5.1.2 1 915 Protección frente a mass parameter assignment en frameworks. Not Applicable lavadero.py No existe binding automático ni modelos; las opciones se asignan explícitamente a atributos (prelavadoamano, secadoamano, encerado).
    Input Validation Requirements 5.1.3 1 20 Validación positiva (allow list) de toda entrada (formularios, REST, URL, etc.). Not Applicable main_app.py, lavadero.py No hay formularios, JSON ni parámetros libres; solo se manejan flags booleanos definidos en código.
    Input Validation Requirements 5.1.4 1 20 Validación de datos estructurados contra esquema (longitud, patrón, etc.). Not Applicable lavadero.py No se tratan datos estructurados de usuario (teléfono, tarjeta, etc.), solo números de fase y un acumulador de ingresos.
    Input Validation Requirements 5.1.5 1 601 Control de destinos de redirecciones/forwards mediante allow list. Not Applicable main_app.py No existen redirecciones ni forwards de URL; es una aplicación de consola sin navegación web.
    Sanitization and Sandboxing Requirements 5.2.1 1 116 Sanitizar HTML procedente de editores WYSIWYG. Not Applicable main_app.py No se acepta ni genera HTML; únicamente salida de texto plano en consola.
    Sanitization and Sandboxing Requirements 5.2.2 1 138 Sanitizar datos no estructurados (caracteres permitidos, longitud). Not Applicable main_app.py, lavadero.py No se procesan cadenas libres de usuario; las entradas son parámetros booleanos internos.
    Sanitization and Sandboxing Requirements 5.2.3 1 147 Sanitizar entradas antes de pasarlas a sistemas de correo (SMTP/IMAP). Not Applicable main_app.py La aplicación no envía correos ni interactúa con sistemas SMTP/IMAP.
    Sanitization and Sandboxing Requirements 5.2.4 1 95 Evitar eval() y ejecución dinámica de código, o sanear/sandboxear entrada si se usa. Valid main_app.py, lavadero.py No se usa eval ni ejecución dinámica de código; solo llamadas directas a funciones y métodos de Lavadero.
    Sanitization and Sandboxing Requirements 5.2.5 1 94 Protección frente a template injection. Not Applicable main_app.py No hay motores de plantillas ni renderizado de vistas HTML/templating.
    Sanitization and Sandboxing Requirements 5.2.6 1 918 Protección frente a SSRF validando URLs/metadatos HTTP. Not Applicable main_app.py, lavadero.py No se realizan peticiones HTTP salientes ni se accede a URLs de usuario; SSRF no aplica.
    Sanitization and Sandboxing Requirements 5.2.7 1 159 Sanitizar o sandboxear contenido SVG scriptable. Not Applicable main_app.py No se manejan ficheros SVG ni gráficos; solo texto.
    Sanitization and Sandboxing Requirements 5.2.8 1 94 Sanitizar/sandboxear lenguajes de plantilla scriptables (Markdown, CSS, XSL, BBCode, etc.). Not Applicable main_app.py No se procesan contenidos Markdown, CSS, XSL ni BBCode procedentes de usuario.
    Output encoding and Injection Prevention Requirements 5.3.1 1 116 Encoding de salida adecuado al contexto (HTML, JS, URL, etc.). Not Applicable main_app.py No hay contextos HTML/JS/URL/headers; la salida es texto plano a consola sin datos de usuario.
    Output encoding and Injection Prevention Requirements 5.3.2 1 176 Preservar charset y locale del usuario al hacer encoding de salida. Not Applicable main_app.py No se realiza encoding específico ni se cambian juegos de caracteres; se usan cadenas internas de Python.
    Output encoding and Injection Prevention Requirements 5.3.3 1 79 Escapado de salida para proteger contra XSS (reflected, stored, DOM). Not Applicable main_app.py La aplicación no corre en navegador ni genera HTML, por lo que XSS no aplica.
    Output encoding and Injection Prevention Requirements 5.3.4 1 89 Uso de queries parametrizadas/ORM para prevenir SQL injection. Not Applicable lavadero.py No existe base de datos ni se construyen queries SQL/NoSQL; los datos se mantienen en memoria.
    Output encoding and Injection Prevention Requirements 5.3.5 1 89 Escapado específico (p.ej. SQL) cuando no hay queries parametrizadas. Not Applicable lavadero.py Al no haber consultas a BBDD, no es necesario aplicar mecanismos de escapado de SQL.
    Output encoding and Injection Prevention Requirements 5.3.6 1 830 Protección frente a JavaScript/JSON injection, DOM XSS, etc. Not Applicable main_app.py No se genera ni ejecuta JavaScript ni JSON en clientes; no hay superficie para inyección JS/JSON.
    Output encoding and Injection Prevention Requirements 5.3.7 1 943 Protección frente a LDAP injection. Not Applicable lavadero.py La aplicación no usa LDAP ni realiza consultas a directorios.
    Output encoding and Injection Prevention Requirements 5.3.8 1 78 Protección frente a OS command injection. Valid main_app.py, lavadero.py No se ejecutan comandos del sistema operativo (os.system, subprocess, etc.), por lo que no hay riesgo de OS command injection.
    Output encoding and Injection Prevention Requirements 5.3.9 1 829 Protección frente a Local/Remote File Inclusion (LFI/RFI). Not Applicable main_app.py No se abren ficheros basados en rutas de usuario; no hay LFI/RFI.
    Output encoding and Injection Prevention Requirements 5.3.10 1 643 Protección frente a XML/XPath injection. Not Applicable lavadero.py No se procesan XML ni se utilizan consultas XPath; riesgo de XML/XPath injection inexistente.
    Memory, String and Unmanaged Code Requirements 5.4.1 2 120 Uso de primitivas seguras de memoria/cadenas frente a overflows. Not Applicable lavadero.py La app es de Nivel 1 y está escrita en Python gestionado, sin punteros ni código nativo; estos controles aplican más a C/C++.
    Memory, String and Unmanaged Code Requirements 5.4.2 2 134 Evitar que format strings tomen entrada potencialmente hostil. Valid main_app.py, lavadero.py Las format strings usadas en print son literales constantes, no construidas con entrada potencialmente hostil.
    Memory, String and Unmanaged Code Requirements 5.4.3 2 190 Validación de signo, rango e input para evitar integer overflows. Not Applicable lavadero.py Solo se manejan contadores y precios pequeños en coma flotante; no hay cálculos que puedan provocar integer overflow y la app es Nivel 1.
    Deserialization Prevention Requirements 5.5.1 1 502 Integridad/cifrado en objetos serializados. Not Applicable main_app.py No se serializan objetos ni se almacenan datos usando formatos binarios/serializados.
    Deserialization Prevention Requirements 5.5.2 1 611 Configuración segura de parsers XML (sin entidades externas) para evitar XXE. Not Applicable main_app.py No se usan parsers XML ni se procesan entidades externas; no hay superficie para XXE.
    Deserialization Prevention Requirements 5.5.3 1 502 Evitar o proteger la deserialización de datos no confiables (JSON/XML/YAML, etc.). Not Applicable main_app.py, lavadero.py No se deserializan datos JSON/XML/YAML de fuentes externas; solo se usan estructuras en memoria.
    Deserialization Prevention Requirements 5.5.4 1 95 Uso de JSON.parse en lugar de eval() para parsear JSON en entornos JS. Not Applicable main_app.py No se parsea JSON ni se usa eval para interpretar datos; no se reciben documentos JSON.

    Conclusiones sobre validación de entrada¶

    • La aplicación no expone interfaces web ni APIs, y no recibe entrada libre de usuario, por lo que la mayoría de requisitos de validación, sanitización y encoding de salida resultan Not Applicable.
    • Los requisitos aplicables (no uso de eval, ausencia de comandos de sistema y uso de format strings constantes) se cumplen en el código actual, lo que reduce la superficie de ataque relacionada con inyección y ejecución de código.
